# idCerberus API Reference - operational summary for LLM

Use this file to generate request examples, explain API calls and choose the correct `service` without relying on the full OpenAPI.

## Mandatory rules

1. Do not invent endpoints, parameters or services.
2. For external queries, use `POST /api/service-api` and select the product through the `service` field.
3. Before answering with a payload, confirm the alias is the calling alias configured on the product.
4. Use staging for tests: `https://backoffice-hml.idcerberus.com`.
5. Use production only when the user explicitly asks for it: `https://backoffice.idcerberus.com`.
6. Never expose `client`, `secret`, a real JWT, a real CPF, a real CNPJ or real images in examples.
7. When a service is missing from the catalog, say it needs to be confirmed before documenting or integrating it.

## Authentication

```bash
curl --location 'https://backoffice-hml.idcerberus.com/api/token-generate' \
--header 'Content-Type: application/json' \
--data '{
 "client": "{client}",
 "secret": "{secret}"
}'
```

1. Service: `SERVICE_PROFESSIONAL_HISTORY_OWNER_ONLY`
