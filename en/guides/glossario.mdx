# Glossary

This page explains common terms used in the guides and the API Reference.

| Term | Meaning |
| --- | --- |
| API | A way for one system to talk to another system through requests |
| Endpoint | A specific URL that runs an operation |
| Request | A call sent to the API |
| Response | The response returned by the API |
| HTTP method | The type of operation, like `GET` or `POST` |
| Header | Information sent along with the call, like authentication or content type |
| Body | The content sent in the request, usually in JSON |
| JSON | The data format used in the API's examples |
| Base URL | The environment's starting address, like staging or production |
| HML | The staging environment, used for testing |
| Production | The environment used for real queries |
| Token | A temporary code used to authenticate calls |
| JWT | The format of the authentication token returned by the API |
| Bearer | The authentication type used in the `Authorization` header |
| `client` | The application identifier used to generate a token |
| `secret` | The application secret used to generate a token |
| `service` | The field that defines which product runs in `POST /api/service-api` |
| CPF | Individual taxpayer document |
| CNPJ | Business taxpayer document |
| `result` | The object with the data returned by the service |
| `status.code` | Technical processing code |
| `status.message` | Technical processing message |
| `externalId` | External query identifier, when returned |
| OCR | Extracting data from documents via image |
| Webhook | An automatic notification idCerberus sends to your URL when an onboarding changes status |
| `id-cerberus-token` | The header sent in every webhook call, used to confirm it came from idCerberus |
| FaceMatch | Facial comparison between two images |
| Liveness | Proof-of-life validation |
| KYC | Customer knowledge and validation process |
| PEP | Politically exposed person |

## Practical example

In this request:

```json
{
  "service": "SERVICE_PERSON_DATA_ENRICHMENT",
  "cpf": "cpf"
}
```

`service` tells the API which product to run, and `cpf` tells it which
person to query.

In this header:

```txt
Authorization: Bearer {jwt_token}
```

`Authorization` is the header, `Bearer` is the authentication type, and
`{jwt_token}` is the token generated by the API.
