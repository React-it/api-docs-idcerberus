# Service index

Use this index when you already know which product you need to run and want to confirm the exact `service` name before building the call.

<Info>
All the queries below use `POST /api/service-api`. The product executed is defined by the `service` field in the body.
</Info>

## How to search better

Search works best when the term appears as a title, alias or page text. If you do not know the exact alias, search by the type of document, data or problem you want to solve.

<CardGroup cols={2}>
 <Card icon="id-card" title="I have a CPF" href="#individuals">
 Search for `cpf`, `revenue`, `score`, `risk`, `phone`, `email`, `ocr`, `face` or `lawsuits`.
 </Card>
 <Card icon="building" title="I have a CNPJ" href="#businesses">
 Search for `cnpj`, `revenue`, `credit risk`, `partners`, `domains`, `CNPJ card` or `compliance`.
 </Card>
 <Card icon="image" title="I have an image" href="/en/guides/service-api/sobre-ocr-service-api">
 Search for `OCR`, `CNH`, `RG`, `CNPJ card`, `proof of address`, `base64` or `image1`.

</CardGroup>

<Warning>
Before running the call, confirm which service is enabled on the client's product. The `service` field must receive exactly the public value shown in the catalog.
</Warning>

In practice: copy the `Service` value from the card or accordion of the product and send that value in the request body. The documentation does not expose internal integration aliases.
