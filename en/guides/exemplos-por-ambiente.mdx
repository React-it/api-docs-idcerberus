# Examples by environment

Use this page when you need to quickly check the same call in staging and
production. The request structure is the same; what changes is the base
URL.

<Warning>
Use credentials, a token, and a base URL from the same environment. A
staging token shouldn't be used in production, and a production token
shouldn't be used in staging.
</Warning>

## Base URLs

| Environment | Base URL | When to use |
| --- | --- | --- |
| Staging | `https://backoffice-hml.idcerberus.com` | Testing, payload validation, and staging the integration |
| Production | `https://backoffice.idcerberus.com` | Real operation, with production credentials |

## Generate a token

<Tabs>
<Tab title="Staging">

```bash
curl --location 'https://backoffice-hml.idcerberus.com/api/token-generate' \
--header 'Content-Type: application/json' \
--data '{
  "client": "{client}",
  "secret": "{secret}"
}'
```

</Tab>
<Tab title="Production">

```bash
curl --location 'https://backoffice.idcerberus.com/api/token-generate' \
--header 'Content-Type: application/json' \
--data '{
  "client": "{client}",
  "secret": "{secret}"
}'
```

</Tab>
</Tabs>

## CPF query

<Tabs>
<Tab title="Staging">

```bash
curl --location 'https://backoffice-hml.idcerberus.com/api/service-api' \
--header 'Content-Type: application/json' \
--header 'Authorization: Bearer {jwt_token}' \
--data '{
  "service": "SERVICE_RFB_PF",
  "cpf": "cpf",
  "birthDate": "yyyy-MM-dd (optional)"
}'
```

</Tab>
<Tab title="Production">

