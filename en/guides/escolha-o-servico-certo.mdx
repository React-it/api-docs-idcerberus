# Choose the right service

Use this page to go from a business need to the `service` codes you should
use in `POST /api/service-api`.

Useful search terms: CPF Federal Revenue, RFB PF, CNPJ Federal Revenue, RFB
PJ, KYC PF, KYC PJ, OCR, document extraction, FaceMatch, facial comparison,
Liveness, proof of life, fraud score, financial risk, electoral data, active
debts, protests, business owners, and compliance.

<Info>
  This page is a decision guide by need, not the complete list of services.
  The full technical catalog lives in
  [Individual Services](/en/guides/servicos-pessoa-fisica) and
  [Business Services](/en/guides/servicos-pessoa-juridica).
</Info>

## Before the tables, what's your role?

<Tabs>
<Tab title="I'm in product or business">
You don't need to read `SERVICE_SOMETHING` codes to decide anything. Skip
straight to the table for your need (validate identity, analyze risk,
validate contact, analyze a company) and read the **Need** column. It
describes what the service does in plain language. The code in the column
next to it is just what your technical team will copy afterward.

If you'd rather have a conversation than a table, start with the
[Overview](/en/guides/visao-geral), which explains what a service and an
onboarding are without technical jargon.
</Tab>
<Tab title="I'm a dev integrating the API">
Follow the normal process: find the service in the table, copy the exact
code, and go to the [API Reference](/api-reference/authorization/generate-api-token)
to get the full contract (payload, response, errors). If you haven't made
your first call yet, start with the [Quickstart](/en/guides/quickstart)
before choosing the final service.
</Tab>
<Tab title="I'm on mobile or using the SDK">
This page is about `POST /api/service-api` (single-shot queries). If your
case is capturing a user's document and selfie in an app, the flow is
different. See [Onboarding via SDK](/en/guides/onboarding-sdk). You can
still come back here later to complement onboarding with extra single-shot
queries.
</Tab>
<Tab title="I'm QA or working in staging">
The tables below apply to staging and production with no code difference.
After choosing the service, see [Environments](/en/guides/ambientes) to confirm
the URL and test credentials, and [Status and errors](/en/guides/status-e-erros)
to know how to interpret responses before reporting a bug.
</Tab>
</Tabs>

## How to decide

1. Identify whether the query is for an individual, a business, onboarding, or a customer.
2. Confirm the main document: `cpf`, `cnpj`, `phone`, images, or `tokenOnboarding`.
3. Choose the service by business need, not by its technical name.
4. Copy the exact name from the [Service index](/en/guides/indice-de-services).
5. Build the request in staging.
6. Read `status.code`, `status.message`, and `result` before releasing to production.

<Tip>
If the person integrating doesn't know the API, start with the CPF, CNPJ,
FaceMatch, or document analysis examples in
[Examples by environment](/en/guides/exemplos-por-ambiente).
</Tip>

## Validate a person's identity

| Need | Recommended services | When to use |
| --- | --- | --- |
| Confirm CPF registration data | `SERVICE_PERSON_DATA_ENRICHMENT`, `SERVICE_RFB_PF` | Validate name, date of birth, registration status, and Federal Revenue source |
| Update CPF data with an on-demand query | `SERVICE_RFB_PF_ON_DEMAND` | Fetch registration data at request time |
| Extract data from a document | `SERVICE_OCR` | Read RG/CIN, CNH, OAB, RNE/CRNM, passport, and auto-identification |
| Compare a selfie and a document | `SERVICE_FACE_MATCH` | Validate whether two images belong to the same person |
| Query government biometrics | `SERVICE_DATAVALID_CNH` | Get a similarity score against government databases |
| Validate a CNH with DataValid | `SERVICE_DATAVALID_CNH` | Support document validation with a document-validation integration |
| Run a full document analysis | `SERVICE_DIGITAL_DOCUMENTOSCOPY` | Extract data and match a document with a selfie in a single flow |

## Build a complete onboarding

| Step | Services or endpoints |

## Common combinations

| Flow | Recommended combination |
| --- | --- |
| Simple CPF registration | `SERVICE_RFB_PF` + `SERVICE_PERSON_DATA_ENRICHMENT` |
| Onboarding with a document | `SERVICE_OCR` + `SERVICE_FACE_MATCH` |
| Individual KYC | `SERVICE_PEP` + certificates + debts + risk score |
| Business registration | `SERVICE_RFB_PJ` + `SERVICE_CORPORATE_DATA_ENRICHMENT` + `SERVICE_SINTEGRA_CONSULTATION` |
| Business KYC | PJ data + business owners + owners' KYC + debts + protests |
