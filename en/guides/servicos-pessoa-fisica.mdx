# Individual Services

Individual services let you query, validate, and enrich CPF data across
onboarding, KYC, fraud prevention, registration analysis, biometrics,
documents, compliance, and electoral data flows.

All of them run through the central services endpoint. The `service` field
defines which product will be processed, and the other fields vary
depending on the query chosen.

Before building the body, check the client's product to see which alias is
enabled. That's the value that should go in the `service` field.

```http
POST /api/service-api
```

In the `curl` examples, `{base_url}` represents the URL of the chosen
environment:

| Environment | Base URL |
| --- | --- |
| Staging | `https://backoffice-hml.idcerberus.com` |
| Production | `https://backoffice.idcerberus.com` |

Example request:

```json
{
  "service": "SERVICE_PERSON_DATA_ENRICHMENT",
  "cpf": "cpf"
}
```

## How to use this catalog

This is the full technical reference for individuals. Use it when you need
a service's full contract. To navigate by goal or product family first, see
[Choose the right service](/en/guides/escolha-o-servico-certo),
[Service matrix](/en/guides/matriz-de-servicos), or
[Service families](/en/guides/service-api/familias-de-servicos).

Use this page to look up the full list of CPF services, their `service`
codes, main fields, and more extensive request and response examples.

<Warning>
  The catalog shows the functional name and the documented alias for the
  service. If the client's product was configured with a short alias, use
  the product's alias in the `service` field. This avoids access errors
  even when the product is active.
</Warning>

Quick step to avoid errors:

1. Open the client's product in the Backoffice.
2. Confirm the alias enabled for the service.
3. Send that alias in the `service` field.
4. Use the table's other fields as the query's main input.

| Documented alias | Product's short alias |
| --- | --- |
| `SERVICE_DIGITAL_DOCUMENTOSCOPY` | `SERVICE_DOCUMENTOSCOPY` |
| `SERVICE_DIGITAL_DOCUMENTOSCOPY_CONSULT` | `SERVICE_DIGITAL_DOCUMENTOSCOPY` |
| `SERVICE_ECONOMIC_RELATIONSHIP` | `economic_relationships` |
| `SERVICE_EMAIL_VALIDATION` | `SERVICE_EMAIL_VALIDATION1` |
| `SERVICE_PROTEST_CLEARANCE_CERTIFICATE`, `SERVICE_PROTEST_PF` | `SERVICE_PROTEST_CLEARANCE_CERTIFICATE` |

<Info>
  OCR, document analysis, FaceMatch, and Liveness need a real image/base64,
  URL, or `key` to return complete data. A short payload helps validate
  authentication, product access, and the basic call format, but doesn't
  validate the full processing return.
</Info>

## Status and errors

In the query response, the API includes a `status` object that indicates
the query's status. This object has `code` and `message` attributes, used
to interpret technical processing.

```json
{
  "status": {
    "code": 200,
    "message": "Success"
  }
}
```

For handling details, see [Status and errors](/en/guides/status-e-erros).

## Advanced queries added

Some services return consolidated information or analyses derived from
complementary sources. They follow the same call pattern for the
`POST /api/service-api` endpoint, but can have broader responses depending
on data availability for the query.

| Service | When to use it | Body example |
| --- | --- | --- |
| `SERVICE_RFB_PF_ON_DEMAND` | Look up the CPF at the Federal Revenue at query time | `{ "service": "SERVICE_RFB_PF_ON_DEMAND", "cpf": "cpf" }` |
| `SERVICE_PERSON_DATA_MODELING` | Consolidate modeling data, contacts, relationships, lawsuits, and addresses | `{ "service": "SERVICE_PERSON_DATA_MODELING", "cpf": "cpf" }` |
| `SERVICE_PERSON_AI_PROMPT` | Generate an analytical text summary from the person's consolidated data | `{ "service": "SERVICE_PERSON_AI_PROMPT", "cpf": "cpf" }` |
| `SERVICE_DATAVALID_CNH` | Validate a CNH with document-validation support | `{ "service": "SERVICE_DATAVALID_CNH", "cpf": "cpf", "image1": "base64" }` |
| `SERVICE_FINANCIAL_RISK_SCORE` | Query the financial risk score | `{ "service": "SERVICE_FINANCIAL_RISK_SCORE", "cpf": "cpf" }` |
| `SERVICE_PF_FINANCIAL_AND_ADDRESS` | Combine registration data, addresses, and financial information | `{ "service": "SERVICE_PF_FINANCIAL_AND_ADDRESS", "cpf": "cpf" }` |
| `SERVICE_PROFESSIONAL_HISTORY_OWNER_ONLY` | Return professional history where the person appears as the account holder or partner | `{ "service": "SERVICE_PROFESSIONAL_HISTORY_OWNER_ONLY", "cpf": "cpf" }` |
| `SEVICE_ONLINE_BETTING_PROPENSITY` | Assess propensity for online betting | `{ "service": "SEVICE_ONLINE_BETTING_PROPENSITY", "cpf": "cpf" }` |

<Warning>
  The alias `SEVICE_ONLINE_BETTING_PROPENSITY` is documented without the
  letter `R` in `SERVICE` because that's the spelling implemented in the
  backend. Don't change this spelling without technical validation, since
  the call may stop being recognized.
</Warning>

## Examples

### Individual data enrichment

The individual data enrichment query returns information about an
individual that exists in the Federal Revenue's site. The return can
include registration status, the query's protocol, an indication of death
when available, and other information related to the queried CPF.

This query's information is obtained from the Federal Revenue's public
individual query.

```http
POST /api/service-api
```

Authorization:

```http
Authorization: Bearer {jwt_token}
Content-Type: application/json
```

Body:

```json
{
  "service": "SERVICE_PERSON_DATA_ENRICHMENT",
  "cpf": "cpf"
}
```

Main response fields:

| Field | Description |
| --- | --- |
| `result.cpf` | CPF |
| `result.status` | Status in the Federal Revenue's base |
| `result.statusDate` | Date of the status in the Federal Revenue's base |
| `result.name` | Name |
| `result.fatherName` | Father's name |
| `result.motherName` | Mother's name |
| `result.birthdate` | Date of birth |
| `result.birthCountry` | Country of birth |
| `result.dead` | Indication of death |
| `result.deathYear` | Year of death |
| `result.gender` | Gender |
| `result.age` | Age |
| `result.origin` | Source of the information |
| `result.fiscalRegion` | CPF's tax region |
| `result.numberOfPeopleWithTheSameName` | Number of people with the same full name |
| `result.nameWordCount` | Number of names in the full name |
| `result.nameUniqueScore` | Name uniqueness score, where `1` means unique and `0` extremely common |
| `status.code` | Status message code |
| `status.message` | Status code message |

Example with `curl`:

```bash
curl --location '{base_url}/api/service-api' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Bearer {jwt_token}' \
  --data '{
    "service": "SERVICE_PERSON_DATA_ENRICHMENT",
    "cpf": "cpf"
  }'
```

Example response:

```json
{
  "result": {

    "name": "PERSON NAME",
```

```http
POST /api/service-api
```

Authorization:

```http
Authorization: Bearer {jwt_token}
Content-Type: application/json
```

Body:

```json
{
  "service": "SERVICE_OCR",
  "documentType": "CNH",
  "image1": "base64"
}
```

| Document | Value |
| --- | --- |

| RG / CIN | `RG` |
| OAB | `OAB` |

```json
  "service": "SERVICE_ELECTORAL_PROVIDERS_CPF",
  "cpf": "cpf"
}
```

Main response fields:

| Field | Description |
| --- | --- |
| `name` | Name of the individual or entity |
| `partiesThatReceivedProvision` | List of parties that received provisions |
| `electionProvisionData` | Detailed data on electoral provisions |
| `politicianBallotNumber` | Ballot number of the politician who received the provision |
| `politicianFullName` | Full name of the politician who received the provision |
| `politicianDocNumber` | Politician's document number |
| `partyName` | Name of the party that received the provision |
| `provisionRequester` | Provision requester |
| `electionYear` | Election year |
| `applicationRole` | Office the candidate ran for |
| `numberOfProvisions` | Number of provisions made |
| `totalProvisionValue` | Total value of provisions |
| `crossDonationFlagFound` | Indicates whether a cross donation was found |
| `entityCrossDonationValue` | Cross donation value by the entity |
| `entityCrossDonationYield` | Cross donation yield by the entity |
| `crossDonationRelationshipLevel` | Cross donation relationship level |
| `minProvisionValue` | Minimum provision value |
| `maxProvisionValue` | Maximum provision value |
| `avgProvisionValue` | Average provision value |
