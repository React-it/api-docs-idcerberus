# How to use this documentation

The documentation is organized to support discovery, flow design, and
technical implementation. The goal is to keep you from having to search
through a large collection of requests with no context.

<Info>
  This page explains how the SITE is organized (guides vs. catalog vs. API
  Reference). If you want a recommended path by role or goal, see
  [Documentation map](/en/guides/mapa-da-documentacao). If you just want good
  search terms, see [Quick search](/en/guides/busca-rapida).
</Info>

## The most common path

<Steps>
  <Step title="Start with the Quickstart">
    Use the [Quickstart](/en/guides/quickstart) to validate credentials,
    generate a token, and run your first call with Postman, Windows, macOS,
    or Linux.
  </Step>
  <Step title="Understand the domain">
    Use the Individuals, Businesses, and Main flows guides to understand
    when each product makes sense.
  </Step>
  <Step title="Choose the service codes">
    Use [Choose the right service](/en/guides/escolha-o-servico-certo) when
    you know the business problem but don't yet know which queries to
    combine.
  </Step>
  <Step title="Implement in the API Reference">
    Use the [API Reference](/en/api-reference/autorização/gerar-token-de-api)
    to copy payloads, check parameters, and map responses.
  </Step>
</Steps>

## If you don't know where to run it from

You don't need to start by writing code. The simplest way is to test in
Postman, because the tool keeps the URL, headers, and body separated in
tabs.

Once the call works in Postman, you can repeat the same request in the
terminal:

| System | How to test |
| --- | --- |
| Windows | PowerShell or CMD with `curl.exe` |
| macOS | Terminal with `curl` |
| Linux | Terminal with `curl` |

The [Quickstart](/en/guides/quickstart) shows this step by step with
examples for each environment.

## Guides vs API Reference

Use the guides to decide what to consume. Use the API Reference to
implement the call.

| Question | Where to look |
| --- | --- |
| Which service solves my case? | [Choose the right service](/en/guides/escolha-o-servico-certo) |
| How do I authenticate? | [Authentication](/en/guides/autenticacao) |
| How does onboarding via SDK work? | [Onboarding via SDK](/en/guides/onboarding-sdk) |
| Which fields does a service return? | Technical catalog and API Reference |
| Which body should I send? | API Reference |
| How do I handle failures? | [Status and errors](/en/guides/status-e-erros) |

## When to use the technical catalog

The technical catalog is useful when you need to check larger field lists
or compare services within the same domain.

1. [Individual Services](/en/guides/servicos-pessoa-fisica)
2. [Business Services](/en/guides/servicos-pessoa-juridica)

For operational endpoints, like querying or changing a customer, use the
API Endpoints section in the API Reference.

## When to use examples by language

Use [Examples by language](/en/guides/exemplos-por-linguagem) when you want
to speed up your initial implementation in `curl`, Node.js, Python, or C#.

After validating the flow, swap the `service` and the payload fields for
the product you want.
