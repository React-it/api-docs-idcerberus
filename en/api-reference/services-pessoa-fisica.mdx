<Info>
Explicit catalog of individual (PF) services available via API, with expected fields and request examples. All services use `POST /api/service-api`; the product executed is defined by the `service` field in the body.
</Info>

<Warning>
Use exactly the value shown in `Service`. Do not send an internal alias or integration name.
</Warning>

## How to interpret any response

<CardGroup cols={2}>
 <Card icon="database" title="Useful data">
 Read the `result` object first. It concentrates the business fields the client should consume.
 </Card>
 <Card icon="gauge" title="Technical status">
 Use `status.code` and `status.message` to understand whether the call processed, was refused or failed.
 </Card>
 <Card icon="magnifying-glass" title="Traceability">
 Keep `externalId` for tests, support and audits. It is the most practical identifier for the query.
 </Card>
 <Card icon="file-lines" title="Clean contract">

<Accordion title="Biometric score" id="SERVICE_DATAVALID_CNH">

**Service:** `SERVICE_DATAVALID_CNH`

**When to use:** Use to compare the submitted image against available biometric databases and return the similarity.

**What it returns:** Returns CNH document validation, including biometric score, facial similarity, validation status and checked fields.

<CardGroup cols={2}>
 <Card icon="arrow-right-to-bracket" title="Input">
 Required fields: `service`, `cpf`, `image1`.
 </Card>
 <Card icon="list-check" title="Result">
 Main fields in `result`: `cpf`, `biometricScore`, `validated`, `validationStatus`.
 </Card>
 <Card icon="circle-info" title="Call status">
 Use `status.code` and `status.message` to understand whether the query processed correctly.
 </Card>
 <Card icon="sliders" title="Optional fields">
 No optional field mapped in this example.
 </Card>
</CardGroup>

**Endpoint:** `POST /api/service-api`

**Required fields:** `service`, `cpf`, `image1`

**Optional fields:** No optional field mapped in this example.

### Step by step

1. Generate the token at `POST /api/token-generate` and send it in the `Authorization: Bearer {jwt_token}` header.
2. Build the body with the exact `service` and the required fields listed below.
3. Run `POST /api/service-api` in the chosen environment.
4. Check `status.code` and `status.message` to validate the technical processing.
5. Map the `result` fields per the summary and the response example for this service.

```json
  "image1": "{base64Image}"
}
```

### Body fields

| Field | Required | Description |
| --- | --- | --- |
| `service` | Yes | Exact code of the product that will be executed by the central endpoint. |
| `cpf` | Yes | The queried individual's CPF. |
| `image1` | Yes | First image sent as base64 or an equivalent reference, depending on the product. |

### Main result fields

| Field | Description |
| --- | --- |
| `result.cpf` | CPF related to the query result. |
| `result.biometricScore` | Field returned in the result object for the client's consumption. |
| `result.validated` | Date returned by the query, depending on the service context. |
| `result.validationStatus` | Field returned in the result object for the client's consumption. |
