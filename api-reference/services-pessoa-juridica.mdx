<Accordion title="OCR de cartão CNPJ" id="SERVICE_OCR_CNPJ_CARD">

**Service:** `SERVICE_OCR_CNPJ_CARD`

**Quando usar:** Use para extrair dados de documentos enviados em base64 ou por URL.

**O que retorna:** Retorna dados extraídos do cartão CNPJ enviado por imagem, incluindo CNPJ, tipo do documento e texto OCR quando disponível.

<CardGroup cols={2}>
 <Card title="Entrada">
 Campos obrigatórios: `service`, `image1`.
 </Card>
 <Card title="Resultado">
 Principais campos em `result`: `cnpj`, `docType`, `genericOcr`.
 </Card>
 <Card title="Status da chamada">
 Use `status.code` e `status.message` para entender se a consulta processou corretamente.
 </Card>
 <Card title="Campos opcionais">
 Nenhum campo opcional mapeado neste exemplo.
 </Card>
</CardGroup>

**Endpoint:** `POST /api/service-api`

**Campos obrigatórios:** `service`, `image1`

**Campos opcionais:** Nenhum campo opcional mapeado neste exemplo.

### Guia de OCR

Para payloads prontos, qualidade de imagem e diagnóstico de erro, consulte [OCR via Service API](/guides/service-api/sobre-ocr-service-api).

### Payload mínimo

```json
{
  "service": "SERVICE_OCR_CNPJ_CARD",
  "image1": "BASE64_DO_CARTAO_CNPJ"
}
```

### Retorno limpo esperado

```json
{
  "result": {
    "cnpj": "cnpj",
    "docType": "CNPJ_CARD",
    "genericOcr": "texto extraído do cartão CNPJ"
  },
  "status": {
    "code": 200,
    "message": "Success"
  },
  "externalId": "{externalId}"
}
```

### Erro comum

```json
{
  "result": {},
  "status": {
    "code": 400,
    "message": "CNPJ não encontrado no cartão CNPJ"
  },
  "onboardingStatus": "REFUSED",
  "externalId": "{externalId}"
}
```

### Passo a passo

1. Gere o token em `POST /api/token-generate` e envie no header `Authorization: Bearer {jwt_token}`.
2. Monte o body com o `service` exato e os campos obrigatórios listados abaixo.
3. Execute `POST /api/service-api` no ambiente escolhido.
4. Confira `status.code` e `status.message` para validar o processamento técnico.
5. Mapeie os campos de `result` conforme o resumo e o exemplo de response deste service.

<Accordion title="Endereços estendidos" id="SERVICE_ADDRESSES_EXTENDED_CNPJ">

**Service:** `SERVICE_ADDRESSES_EXTENDED_CNPJ`

**Quando usar:** Use para consultar todos os endereços associados a um CNPJ, incluindo os endereços atuais, os históricos e indicadores de qualidade de cada um (quão validado e quão recente é o endereço).

**O que retorna:** Retorna a lista completa de endereços encontrados para a empresa (`addresses`) e um resumo agregado com totais e datas (quantos endereços ativos, quantos são comerciais x pessoais, data da primeira e da última passagem confirmada em cada endereço).

 <Card title="Campos opcionais">

### Passo a passo

### Campos principais do result

| Campo | Descrição |
| --- | --- |
| `result.cnpj` | CNPJ consultado, sem máscara. |
| `result.addresses` | Lista com todos os endereços encontrados para a empresa. Ver campos de cada item logo abaixo. |
| `result.addressesExtendedTotal` | Total de endereços encontrados. |
| `result.addressesExtendedTotalActive` | Quantos desses endereços estão ativos atualmente. |
| `result.addressesExtendedTotalWork` | Quantos são endereços comerciais/de trabalho. |
| `result.addressesExtendedTotalPersonal` | Quantos são endereços pessoais/residenciais. |
| `result.addressesExtendedTotalUnique` | Quantidade de endereços únicos (sem duplicidade). |
| `result.addressesExtendedTotalPassages` | Total de "passagens" (confirmações) registradas em todos os endereços. |
| `result.addressesExtendedTotalBadPassages` | Quantas dessas passagens são consideradas de baixa confiabilidade. |
| `result.addressesExtendedOldestPassageDate` | Data da passagem mais antiga entre todos os endereços. |
| `result.addressesExtendedNewestPassageDate` | Data da passagem mais recente entre todos os endereços. |

**Campos de cada item de `result.addresses[]`:**

| Campo | Descrição |
| --- | --- |
| `address` | Logradouro (rua/avenida) do endereço. |
| `number` | Número do endereço. |
| `complement` | Complemento (sala, andar, bloco), quando existir. |
| `neighborhood` | Bairro. |
| `city` | Cidade. |
| `state` | UF. |
| `country` | País. |
| `zipcode` | CEP, sem máscara. |
| `addressType` | Tipo do endereço (ex.: `COMMERCIAL`, `RESIDENTIAL`). |
| `isActive` | `"true"`/`"false"` — se o endereço está ativo atualmente. |
| `isMainForEntity` | `"true"`/`"false"` — se é o endereço principal da empresa. |
| `priority` | Prioridade/relevância do endereço em relação aos demais (quanto menor, mais relevante). |
| `lastValidationDate` | Data da última validação desse endereço específico. |

<Info>
Todos os valores dentro de `addresses[]` são retornados como texto (string), inclusive os booleanos (`"true"`/`"false"`) e números (`"1"`). Faça o parse no seu lado antes de comparar com `true`/`false` ou usar em cálculos.
</Info>
