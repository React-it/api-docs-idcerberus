# Backoffice

## O que é, por que existe, pra que serve

1. **O que é:** a interface web da idCerberus, acessada por login (usuário e
  senha), separada da integração via API. É o mesmo domínio
  (`backoffice-hml.idcerberus.com` / `backoffice.idcerberus.com`) que serve
  os endpoints `/api/...` — veja por que em [Visão geral](/guides/visao-geral).
2. **Por que existe:** nem toda tarefa precisa de código. Acompanhar o volume
  de cadastros, olhar o resultado de um onboarding específico ou testar uma
  consulta pontual não deveria exigir abrir o Postman.
3. **Pra que serve pra você:** é o lugar para visualizar e explorar, não para
  integrar. Sua aplicação continua consumindo dados pela API, SDK ou webhook
  — o backoffice é o painel que o seu time usa por cima disso.

## O que você encontra lá

| Área | Para que serve |
| --- | --- |
| Dashboard | Volume de cadastros, resumo de onboarding, distribuição geográfica e por idade dos clientes processados |
| Onboardings | Lista e detalhe de cada cadastro processado — o mesmo conteúdo que `GET /api/onboarding/report/{tokenOnboarding}` retorna, mas em tela. O detalhe também mostra o histórico de tentativas de webhook daquele onboarding e permite forçar um reenvio manual |
| Consultas rápidas | Rodar uma consulta pontual (CPF, CNPJ, documento com OCR, nome, telefone, face) direto na interface, sem montar payload nem chamar a API |

<Tip>
  Use as consultas rápidas do backoffice para validar rapidamente que um
  service faz o que você espera, antes de replicar a mesma chamada em código
  via `POST /api/service-api`. É o jeito mais rápido de "ver o resultado" sem
  escrever nada.
</Tip>

## Backoffice ou API — qual usar

| Se você precisa... | Use |
| --- | --- |
| Automatizar consultas dentro do fluxo da sua aplicação | API ([Quickstart](/guides/quickstart)) |
| Conduzir um cadastro completo dentro do seu app | SDK ou Cliente Web ([Onboarding via SDK](/guides/onboarding-sdk)) |
| Ser avisado quando um cadastro mudar de status | Webhook ([Webhooks](/guides/webhooks)) |
| Olhar um resultado específico rapidamente, sem codar | Backoffice, tela de Onboardings |
| Testar uma consulta antes de integrar | Backoffice, Consultas rápidas |
| Acompanhar volume e indicadores | Backoffice, Dashboard |

## Dúvidas comuns

<AccordionGroup>
  <Accordion title="O que eu faço no backoffice também está disponível na API?">
    Dashboard e histórico de onboarding refletem os mesmos dados que
    `GET /api/onboarding/report/{tokenOnboarding}` expõe. Consultas rápidas
    usam por baixo os mesmos services de `POST /api/service-api` — é a
    mesma consulta, só que disparada pela tela em vez de código.
  </Accordion>
  <Accordion title="Minha credencial de backoffice é a mesma do client/secret da API?">
    Não. O login do backoffice é usuário e senha, para uma pessoa. `client` e
    `secret` autenticam a sua aplicação. São dois mecanismos de autenticação
    diferentes para o mesmo sistema — veja
    [Autenticação](/guides/autenticacao) para o lado API.
  </Accordion>
  <Accordion title="Consigo configurar webhook pelo backoffice?">
    A configuração de webhook (URL e chave) hoje é feita pela React IT sob
    pedido, não é uma tela de autoatendimento ainda. Veja
    [Webhooks](/guides/webhooks) para como pedir a ativação.
  </Accordion>
</AccordionGroup>
